Network Drives

Network Drives has its own navigation section. It manages Windows SMB mappings and

specific IPv4 host routes, separately from browser SOCKS and application routing.

SYSTEM → Network Drive Routing contains mechanism checks, Enable/Disable

management and Install/Repair. Drive Connections contains import, Add/Edit and

per-drive Connect/Disconnect actions, without the mechanism installation controls.

First setup

An administrator prepares the Linux SMB gateway for the reviewed client address

and file-server addresses. Only TCP 445 is forwarded through the approved GR VPN.

The server previously had IPv4 forwarding disabled. Its owned guard continues

to deny other IPv4 forwarding; existing local SOCKS and SSH services are unaffected.

Do not extend forwarding for another feature without reviewing this guard.

The service loads the guard before enabling forwarding and starts at Linux boot.

No default gateway, DNS or VPN profile is changed.

After installing the app, log in and open Network Drives. Import startup drives

reads the current user's map-drives.cmd without executing it. Drive letters,

shares and usernames are preserved; passwords are stored in the existing master

password vault. Import does not enable routing. Source-script expressions are

rejected rather than executed.

Enable management verifies the prepared server gateway, starts the restricted route helper (using the installed protected task;

otherwise explicit Windows UAC approval is required) and retains the legacy startup script as

map-drives.cmd.disabled. A changed source script blocks activation until a fresh

import. The helper only creates volatile /32 routes for approved GR file servers.

It refuses to overwrite existing host routes belonging to another configuration.

Connection and backup

Server GR routing is primary. The Manager checks each file server independently

through the authenticated server control channel. Three failed checks prepare the

local GR-VPN128 profile. The VPN must connect and provide a route through its own

virtual adapter before that host route switches. Other hosts remain on the server.

Three successful primary checks are required before returning to Server.

The same encrypted SMB credentials and original UNC share are used on both paths.

Existing mapped sessions are not forcibly disconnected during a route change.

Open files can still be interrupted; applications may need to reconnect.

The Manager must run in the tray to monitor and switch these routes. The installed protected task starts the route-helper session without recurring

UAC. Installing or repairing that task requires administrator approval. Closing it releases only its owned

host routes. Local VPN use is leased with the existing fallback ledger, so cleanup

does not stop a VPN still used by SSH or another consumer. A manually running VPN

is preserved. After an unclean process exit, stale lease cleanup runs when local

Manager/native activity resumes.

Connect resumes automatic mapping for one drive. Disconnect pauses that drive for

the current session and does not force open files closed. Disable management first

disconnects its matching mappings safely, releases routes and then releases its VPN

lease. It leaves the retained startup script disabled; restore it only when explicitly

returning to the legacy workflow. No unrelated drive letter is replaced or removed.

SMB TCP reachability is not an authentication or file-permission check. Mapping

failures are recorded with Windows error codes. No Windows security policy is

weakened automatically. Existing SMB mappings with the matching UNC path are

preserved and Windows restores their transport on access.

Validation

Isolated tests cover import and credential separation, allowed IP/drive-letter

scope, independent failure/recovery debounce, injected route failures and rollback,

unowned-route protection, shared VPN leases, and server guard validation. Preview

navigation/UI checks never change routes, map shares or connect VPNs. Live mapping

and outage testing require the feature to be installed and explicitly enabled.

Refresh and reconnect

The NETWORK DRIVES navigation section has Overview for an interactive

connection map (This PC → server GR VPN / local GR VPN backup → individual

drives), and Drive Connections for management. Click a node to inspect its

share, route, reconnect and verification details. Animated edges indicate a

verified route only; the animation is illustrative, not measured SMB traffic.

Failed, paused, unchecked and unmanaged drives have no active edge. The

connections header starts collapsed; click its card to reveal controls, click

again or outside it to close them. Refresh does not reopen closed controls.

Add Drive works while management is enabled and preserves existing connections.

Editing an existing definition still requires management to be disabled. Add accepts a

free drive letter, a literal GR IPv4 share (\\128.1.x.x\share) and optional

credentials. Passwords are stored only in the existing encrypted vault. An edit

keeps the credential identity; a blank password preserves it, while choosing

Windows credentials removes the saved password for that drive. Cancel leaves

the definition unchanged. Existing unrelated Windows mappings are never replaced.

For a new host, Save asks before adding that host's TCP 445 access through the

server GR VPN. The server verifies the expected VPN interface and SMB reachability

first. This operation preserves the approved client address, VPN, previous hosts,

default gateway and DNS; it does not restart services. The gateway allows at most

16 hosts. Existing host authorizations are retained when an edited definition no

longer uses them; deleting firewall authorizations requires separate review.

With management enabled, saving prepares only a new host route and checks/connects

only the new drive. Existing health, pauses and mappings are retained. A failed

definition save rolls back its new route and credential change; a mapping failure

remains visible on the saved drive for retry. With management disabled, Save only

stores the definition; use Enable management afterwards. The protected helper

must be updated for live additions. No other route or mapping is restarted.

Settings → This Computer → Network Drives refresh / reconnect · minutes

controls the background check and retry interval (default 1 minute). Saving takes

effect immediately. The countdown continues across menu changes and while the

Manager stays in the tray. Refresh performs a check immediately and retries

managed drives. Each row shows Auto Reconnect On/Off; a manual Disconnect pauses

that drive for the session, and Connect resumes it. Failed mapping attempts are

counted until a successful mapping. Server/Local transitions still require three

consecutive checks, so their detection time follows the selected interval.

Mechanism status and activity

SYSTEM → Network Drive Routing shows background permissions, helper communication

and the verified route count. Its read-only check runs every five minutes and

with Refresh; it does not start a helper or change routes. The countdown continues

across menu changes. Individual route checks are not displayed as a separate list.

Routing activity records state changes and control requests/results in

Logs/drive-routing.jsonl; the newest 100 records are shown on the page. Full

retained history is available through Open Log Folder. Driver has the same status,

controls and activity structure, with its own driver.jsonl history. These logs

never contain SMB passwords. File access and mapping failures remain in drive/App

logs, separately from route ownership verification.

Operational reminders

Drive routing is Windows /32 routes plus the approved server SMB gateway, not a SOCKS

profile or WinDivert application rule. Keep the Manager in the tray for monitoring.

The existing Auto Reconnect badges, failed-attempt count and refresh countdown show

the drive mechanism; configure intervals in Settings → This Computer. The SYSTEM

page owns mechanism controls and Routing activity; Drive Connections owns per-drive

actions. Both route verification and successful matching mapping/share access matter.

To correct a duplicate letter, inspect its exact UNC first. Disconnect/remove only the

unwanted managed mapping and correct the saved definition; do not remove all mappings.

For example, a letter intended for one server must not be reused as an alias for another

share. Existing unrelated Windows mappings are preserved. Avoid route switching while

files are being edited; route recovery does not guarantee an interrupted write resumed.
