Windows installation and required components

This guide describes the current Windows x64 application. Linux is the optional

remote management server; a macOS desktop release is not supplied by this guide.

Use a complete application release, not a source-code archive or an extension ZIP.

OpenSSH Client and Python run when needed; they are not services to start from

reachable or that an account is authorized.

Install on a new PC

1. Download the application ZIP from the project's Releases page. Compare its

SHA-256 with the release checksums when supplied.

2. Extract the entire ZIP into a permanent directory, for example

%LOCALAPPDATA%\Programs\MikeVas-SOCKS5. Do not run from inside the ZIP.

3. Run Setup.cmd as your normal Windows user. It registers that user's native

browser bridge and creates the desktop shortcut. Setup does not start tunnels,

load WinDivert, configure firewall rules or install startup tunnel tasks.

4. Start the app and create the master password (minimum eight characters) only

on a genuinely new installation. An existing installation should ask to unlock.

If it unexpectedly asks to create one, stop and check the data location first.

5. Open SYSTEM → Components and Refresh. If OpenSSH Client is missing, use its

installation action / Windows Optional Features. Accept elevation only for the

requested installation. Do not install the SSH server on the PC for this purpose.

6. Configure only the features you need using the sections below.

There is no requirement for a .NET SDK, Node.js, pip, SecureCRT or a development

checkout to run the packaged application. Keep all bundled files together.

Browsers

Install the matching store extension when available. For a development test,

Chrome/Edge use Developer mode → Load unpacked and select the extension directory;

Firefox temporary installation selects its manifest.json and lasts only until

the browser restarts. Permanent Firefox distribution requires Mozilla signing.

The store ZIP is an upload package, not a Windows installer.

Run Setup again after moving the application or changing extension registration.

The production Chrome ID is ngofhmcaeaoekahlkpggichinpkkibpf. Native messaging

registration must match the installed extension ID. Firefox may require permission

to run in private windows for its proxy controls.

Select an existing tunnel and Connect, or explicitly select Automatic Routing.

Save policy in the app publishes configuration to the local bridge; it does not

connect a browser. In selected-sites mode, only matching destinations use SOCKS;

others stay Direct. App bypass applies when enabled. Disconnect before changing

the selected tunnel; Select confirms a draft selection and X cancels it.

Direct server SOCKS access can continue while the Manager is closed, including

after a PC restart, provided the browser retained the policy and the server is

reachable and running the tunnel. This does not promise that local backup works

without its local helper, VPN dependencies or unlocked password credentials.

Local tunnels and VPN backup

Create local SSH tunnels with explicit host, SSH port, local SOCKS port and trusted

host identity. Use SSH Key or an encrypted saved Password. Auto Run and Auto

Reconnect are separate settings. Password connections need the master vault

unlocked; an unencrypted SSH key can authenticate without that vault password.

Never distribute private keys or passwords with the application.

Local backups normally have Auto Run Off and start manually or on demand. Auto

Reconnect On means retry after a requested start, not start every stopped backup.

For a VPN-dependent tunnel, select its existing local SoftEther profile in Edit.

Start checks the VPN, connects and waits for it if needed, then starts SSH.

The VPN indicator is green only when connected.

Server → Local fallback needs an explicit matching backup configuration. The same

SSH host, a similar name or port number does not create a backup relationship.

An SSH/SOCKS health check does not prove every remote internal service works.

Destination Checks remain optional and must use reviewed destination addresses.

Application Routing

Choose the executable and proxy/tunnel, then Connect. This uses WinDivert and a

local TCP relay, separately from browser proxy settings and Network Drives.

Current scope is TCP/IPv4; DNS uses the local system. UDP/IPv6 are not covered.

Driver Active and application Routing active are different states. Zero proxy

connections means no current relays; it does not by itself prove a fault.

If security software blocks a required local relay, inspect the specific event

and allow only the reviewed application/connection. Do not disable protection.

Network Drives

1. Have an administrator prepare the Linux GR VPN / SMB gateway for the reviewed

PC address and allowed file-server hosts. See Network Drives.

2. Add a drive in NETWORK DRIVES → Drive Connections, or import the existing

startup script. Import reads definitions; it does not run the script or activate

management. Credentials stay in the encrypted vault.

3. In SYSTEM → Network Drive Routing use Install / Repair once and accept the

Windows administrator prompt. This installs the restricted protected helper;

the main app continues as a normal user. Settings → App → Security provides the

same Install / Repair action. Application Routing and Driver actions also use

this helper without repeated UAC prompts. Updates require a matching helper

version and one administrator approval. New helper files are staged separately;

failed activation attempts restore the previous driver path and retain the

previous task target. Stop active application routing before repair.

4. Enable management there. Check helper / owned-route status and then check SMB

mapping status in Drive Connections. These are separate checks.

5. Keep the app running in the tray for monitoring, reconnect and Server → Local

switching. Configure the drive refresh/reconnect interval in Settings → This

Computer. Route health / failover has a separate interval in seconds (15 by

default); switching requires three consecutive failed/successful health checks.

A green drive requires a matching mapping and a recent successful share-access

check, independently of the server's TCP/445 check. Timed-out share checks are

not reported as healthy. Add Drive supports enabled management; editing existing drives still

requires it to be disabled.

Only approved host routes are managed. Gateway and DNS are preserved. Switching

paths can interrupt open SMB files. Disable management safely releases owned

routes and matching managed mappings; unrelated mappings are preserved. The old

startup script is retained as .disabled, not automatically restored.

Optional Linux server

The Windows package does not provision a Linux server automatically. Follow

Server Management for the restricted management account,

trusted SSH identity, helper and service setup. OpenSSH, Python, SoftEther client

and Linux service/network tools belong on the server as required by its features.

LAN SOCKS exposure and SMB forwarding require explicit administrator review and

restricted client access. Server Auto Run refers to Linux boot, not Windows login.

Verify, update and troubleshoot

- Components: required programs available; SoftEther client responds if used.

- Driver: installed/active only when Application Routing needs it.

- Network Drive Routing: Active only when helper and owned routes verify;

Standby with management off is normal. SMB access is checked separately.

- Browser / Application Connections: current route, tunnel and report age.

- Logs: active issue counts are separate from retained historical records.

Driver and drive routing have their own activity panels and log files.

- A reconnect timeout means the configured SSH endpoint did not respond. It

does not automatically select an unrelated server tunnel. Check VPN dependency,

host/port and the configured fallback mapping before changing credentials.

Before an update, save drafts, tray → Exit, and close extension popups. Replace the

complete package in the same permanent location and rerun Setup if necessary.

If the protected route-helper executable changed, repair it with management

disabled and then re-enable management. No security policy should be disabled.

User data normally lives in %LOCALAPPDATA%\MikeVas_SOCKS5, independently of the

installation folder. Preserve it across upgrades. Never overwrite it with sample

settings. Export settings and the separate encrypted credential transfer only

when explicitly needed; never include keys, vaults, logs or personal settings in

Git or store ZIPs. See Background permissions.

Pre-release verification on a clean computer

The isolated mechanism checks do not replace a clean Windows installation test. Before publishing a release, verify the following on a separate test PC or VM and a new browser profile:

1. Install the release using the documented installer procedure and approve the protected helper once.

2. Check Components and both routing mechanism pages. Verify the packaged runtimes and the optional SoftEther dependency separately.

3. Install the extension, verify native messaging, then test Direct, Manual and Automatic using test endpoints.

4. Open mechanism health → Why this route? to inspect a destination's matching rule, bypass and last reported tunnel check. This preview does not connect or perform DNS; hostname results can differ after DNS resolution for IP network rules.

5. Verify Ignore selections survive reopening the popup, Disconnect remains responsive during a delayed Manager response, and Firefox Restore yields to the browser's own proxy settings.

6. Reboot, verify startup and explicitly configured fallback/recovery, then test uninstall without losing unrelated mappings or browser settings.

Record the Windows/browser versions and actual results. Do not mark this acceptance test complete based only on automated fixtures.
