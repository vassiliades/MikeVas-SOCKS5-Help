MikeVas Connect — current integration Help

Updated 10 November 2026 · EN / Ελληνικά

Manager / Tunnels Help · Connect · Keeper · Workspaces

Install and update

Install MikeVas Connect first, then the required add-ons in each browser profile. Use the Windows x64 package from the MikeVas-Connect releases page. Extract the entire ZIP and run Install-MikeVas-Helper-AI.exe. This executable name and the Helper-AI data/native-host names are retained for compatibility; the application is MikeVas Connect. Close browsers and Thunderbird normally before installation. Existing feature data and shared settings are preserved by the transactional installer.

Open MikeVas Connect from Start. Closing the window hides it; Exit from the tray stops the common runtime. Manager is a separate application and can remain closed for Connect, Keeper, Workspaces and published Server routing. A running Connect runtime is needed for shared native features. Product versions are independent and do not need identical version numbers.

This release provides a Windows x64 Connect package. macOS source/build procedures are separate candidates; this Windows release does not establish Mac acceptance. Browser store submission ZIPs are not proof of store approval or Firefox signing.

Overview and Browsers: what each state proves

Connected for MikeVas Connect proves local engine communication. Keeper Login required concerns the vault session. Workspaces File checks passed proves local shared-file checks, not cloud upload or synchronization to another computer. Connect Connected in Tunnels proves communication with Connect, not the route taken by HTTPS traffic.

Browsers lists live add-on reports by browser and profile, not every open window. Each add-on reports its loaded version and immutable build ID. Loaded build matches disk means the reported build agrees with the matched on-disk payload. Reload required means a newer/different stamped payload is on disk. Rebuild required means files changed without a new build stamp. Disk build not verified means an exact comparison is unavailable; it is not a pass. Firefox can report the loaded identity but its local on-disk comparison is not supported by the Chromium profile resolver.

For unpacked Chrome extensions, open chrome://extensions, locate the existing add-on and click Reload. Do not remove/reinstall it to refresh a build. Reload only the extensions actually installed in that profile. Open the popup and refresh Connect to obtain a new live report. Closed or unreported browsers can remain Pending.

Settings: ownership and safe saves

Settings → This Computer owns local check scheduling and Verify installation. Settings → Keeper owns shared RAM cache and shortcuts. Settings → Workspaces owns the shared file selection and automatic review preference. Browser appearance remains local to each browser profile. Enable shared settings explicitly and Save; unsaved edits and busy operations are guarded.

Settings → Tunnels owns the HTTPS policy URL, one device token protected for the OS user and optional diagnostic delivery. A blank token field preserves the saved token. Removing the local token does not revoke its server registration. Use the server Browser Access / Tunnels Access portal to revoke a device. Do not paste credentials or tokens into support messages.

Tunnels: Direct startup and the remembered profile

Every true new browser session starts in Direct. Closing only one window or waking an MV3 background worker is not a new browser session. The extension remembers the last successfully connected Automatic profile across restarts/reboots; pressing Connect reconnects that profile. If the saved profile is missing, choose another. Selecting a profile without a successful connection does not replace the remembered successful profile.

Configure Tunnel server opens Connect Settings → Tunnels when Connect is available. Save the administrator-provided HTTPS policy URL and device token there once. Tunnels reads the validated policy through Connect; do not enter a second token in every browser. The Manager can remain closed. A server tunnel and the required VPN/network access must already be running independently.

Standalone mode without Connect remains available and stores its own policy URL/token in that browser profile. Manager-managed local tunnels and Server → Local backup require the corresponding Manager/runtime and configured local dependencies. Shared policy access alone does not start local tunnels or promise automatic Local backup.

Test actual routing

Open the Tunnels popup → System health → Test actual routing. Choose an HTTPS destination without a username, password, query or fragment. Clicking the test asks for optional request-observation permission and access to that origin. It sends one fresh HEAD request without cookies, redirects or response body and observes the browser socket for that request.

The result can identify Direct, Server SOCKS5, Local SOCKS5 or Local backup from fresh evidence and the applied route. HTTP status and routing evidence are separate. Not verified is expected when observation/DNS is unavailable, proxy endpoints share an IP, the response is cached, settings are overridden or the route changes during the test. Chromium cannot distinguish proxy ports sharing the same IP. The result covers that request only and is not a VPN or kill-switch guarantee.

Why this route? evaluates the rules for a destination; it is not the network test. The route test does not change routing. Its URL, response body and socket IP are not added to diagnostic history.

Diagnostics and installation checks

Activity and Settings → Tunnels show Pending events, Delivered events retained locally, Rejected Manager files, last acknowledgement and delivery failures. Delivered is not a lifetime count. Saving an event locally is not proof that the server received it. Empty acknowledgements do not advance the successful-delivery timestamp. Corrupt Manager files are quarantined as .json.invalid-* and counted; valid pending events remain retryable.

Diagnostic upload is optional: Settings → Tunnels → Send diagnostic metadata to the server, then Save diagnostic delivery. It uses the configured organization server and protected device token. Fixed event/state/build metadata and device/browser labels may be sent; passwords, MFA codes, vault fields and workspace contents are excluded. Review exports before sharing. Turning upload off does not delete already delivered server history.

After a Windows installation, Connect creates an installation verification report. Rerun it at Settings → This Computer → Verify installation. It checks bundle hashes, native registrations, running bundle identity and live add-on builds. Closed browsers produce Pending. Reload/Rebuild requirements keep the report incomplete. It does not log in to Keeper, fill pages, synchronize Workspaces, test actual browser routing or modify servers.

Keeper and Workspaces

Keeper Sign in opens Connect for account login and MFA. Connect communication, authenticated vault access and successful page filling are three distinct checks. Credentials use a bounded RAM cache. Logout/cache clearing affects the shared session; it does not log out already signed-in websites. Filling requires the user action and does not submit the login form.

Workspaces saves tabs/groups locally. Check changes → Review actions → Apply and confirmation controls synchronization through the configured shared file. Automatic review does not authorize writes or open pages automatically. A successful local file write/check does not prove cloud delivery. Inspect conflicts and uncertain pending operations before retrying; never remove a shared lock merely because it is old.

Ελληνικά — εγκατάσταση, καταστάσεις και νέα εργαλεία

Εγκατάστησε πρώτα το MikeVas Connect και μετά τα πρόσθετα που χρειάζεσαι σε κάθε browser profile. Το Install-MikeVas-Helper-AI.exe και οι παλιές ονομασίες αρχείων παραμένουν για συμβατότητα. Κλείσε κανονικά browsers και Thunderbird πριν την εγκατάσταση. Το Χ κρύβει το Connect· το Exit στο tray σταματά το κοινό runtime. Ο Manager μπορεί να παραμένει κλειστός για τις κοινές λειτουργίες του Connect και τους ήδη ενεργούς Server tunnels.

Browsers: βλέπεις version και build ID που φόρτωσε πραγματικά κάθε πρόσθετο. Reload required: υπάρχει άλλο stamped build στον δίσκο. Rebuild required: άλλαξαν αρχεία χωρίς νέο stamp. Disk build not verified: δεν υπάρχει επαρκής αντιστοίχιση, όχι επιτυχία. Κάνε Reload στο υπάρχον πρόσθετο από chrome://extensions και άνοιξε το popup για νέα αναφορά. Οι κλειστοί browsers μένουν Pending. Στον Firefox δεν γίνεται ακόμη η σύγκριση με τον τοπικό δίσκο.

Settings → Keeper/Workspaces: κοινές λειτουργικές ρυθμίσεις. Η εμφάνιση κάθε browser profile παραμένει τοπική. Settings → Tunnels: HTTPS URL και ένα προστατευμένο device token για τον χρήστη του υπολογιστή. Δεν χρειάζεται δεύτερο token ανά browser. Κενό πεδίο token διατηρεί το υπάρχον· η τοπική αφαίρεσή του δεν αποτελεί ανάκληση στον server.

Σε πραγματικό νέο άνοιγμα browser ξεκινάς Direct. Το Connect θυμάται το τελευταίο Automatic profile που συνδέθηκε επιτυχώς, ακόμη και μετά reboot. Το μπλε Connect το επαναχρησιμοποιεί. Αν το profile δεν υπάρχει πλέον, ζητείται επιλογή. Η αφύπνιση του background worker ή το κλείσιμο ενός μόνο παραθύρου δεν θεωρείται νέο browser session.

Tunnels → System health → Test actual routing: ένα νέο HTTPS HEAD αίτημα με άδεια για τον συγκεκριμένο προορισμό. Εμφανίζει τεκμηριωμένη διαδρομή ή Not verified. Το Connect Connected αποδεικνύει τοπική επικοινωνία, όχι SOCKS5 κίνηση. Κοινή IP διαφορετικών proxy ports δεν διακρίνεται στον Chromium. Το Why this route? εξηγεί κανόνες και δεν κάνει αίτημα δικτύου.

Activity και Settings → Tunnels: Pending, Delivered της διατηρούμενης ιστορίας, Rejected Manager files και τελευταία επιβεβαιωμένη αποστολή. Το upload ενεργοποιείται προαιρετικά με Send diagnostic metadata to the server και Save diagnostic delivery. Settings → This Computer → Verify installation ελέγχει εγκατάσταση/native registrations/builds· δεν αποδεικνύει login, autofill, sync ή πραγματική δρομολόγηση.

Keeper: το Sign in ανοίγει το Connect για login/MFA· δεν υποβάλλονται αυτόματα φόρμες. Workspaces: Check changes → Review actions → Apply και επιβεβαίωση. Τα File checks passed δεν αποδεικνύουν cloud upload. Μην επαναλαμβάνεις αβέβαιες εγγραφές και μη διαγράφεις locks βάσει ηλικίας.

Support and verification limits

Record the product/version, loaded build ID, browser/profile, exact action, timestamp and fixed error category. Never include device tokens, passwords, MFA codes, private keys or unsanitized workspace/vault data. Report code/build tests separately from a live authenticated acceptance test.

The Windows source/build and isolated fixtures do not establish a physical reboot, Mac acceptance, a logged-in Keeper fill, cloud synchronization or final normal-Chrome routing for every installation. An incomplete installation report or Not verified route result must remain visible until that check actually succeeds.
