Daily operating procedures

Use the app to configure and manage resources, the extension to apply browser routing,

and the relevant connection page to verify the actual path. Save configuration before

updating software. The examples below do not authorize production network changes.

Do not combine extension routing and application interception for the same browser.

SOCKS is not the mechanism for Windows mapped drives. Driver Active does not mean

application interception is running. ACTIVE SSH does not prove a remote login works.

Prepare server first and local backup

1. Verify the intended Server SSH Tunnel and its management connection.

2. Define the matching local backup explicitly on that server tunnel. Similar names,

ports or SSH hosts do not automatically establish the relationship.

3. In Edit Local SSH Tunnel choose its existing SoftEther VPN dependency if needed.

4. Keep backup Auto Run Off unless intentionally changing the policy. Auto Reconnect

retries after a requested start; it does not start every stopped local backup.

5. Connect through the desired browser/application consumer. Verified failure prepares

its paired VPN/tunnel; readiness is checked before the route can switch.

6. Use reviewed Destination Checks where an internal VPN failure must be detected

beyond a responding SOCKS listener. Do not invent destination IPs or ports.

Disconnect in our routing UI releases only automatically acquired resources no longer

shared. Closing the external executable is not Application Routing Disconnect.

Manual/shared resources are preserved. Stable server recovery is required before

returning; notifications identify Local activation and return to Server. Keep the

Manager in the tray for local monitoring and ownership cleanup. Incomplete cleanup

can wait for the next successful local/native activity rather than stopping unknown users.

Edit an Automatic Routing policy

1. Select Server or Local. Client IPv4 networks describe the client environment;

rule Destinations describe the remote target.

2. Add/Edit a rule and Save the dialog. Put specific rules before broad networks;

first matching enabled rule wins. Loopback always stays Direct.

3. Drag the left handle to reorder; Esc cancels. Copy to… copies to another profile;

review its endpoint there. Later changes are not mirrored automatically.

4. Use Test a destination for a read-only simulation, then Save policy. A dialog Save

alone does not persist the entire policy. Save / Cancel protects unsaved navigation.

5. Select and activate the profile in the extension. Saving app policy alone does not

connect the browser or start all tunnels.

JSON is the maintained policy. Chromium's generated PAC JavaScript is internal; no

separate manually edited PAC file is required. A hostname simulation without DNS may

not predict a rule dependent on its resolved IP; check the resolved IPv4 as needed.

Browser bypass and Ignore

Follow app bypass is normally On. Matching entries use Direct before routing rules.

View bypass rules → Ignore skips only that entry for this browser profile, shows red

and increments the ignored count. It does not delete the app rule or force SOCKS:

the ordinary rule/default still decides. Localhost/loopback cannot be ignored.

Manual changes: Disconnect → Change tunnel → choose → Select → Traffic rules → Select

→ Connect. X cancels the unconfirmed choice. Automatic changes: Disconnect → choose

the required profile → Use Automatic Routing. Reload destination pages for new connections.

Disconnect applies Direct; Restore browser settings yields to browser/system proxy settings.

Key authentication without a passphrase can run without master vault unlock if the

key/task is ready. Password resources require the unlocked vault. Master login does

not grant new Windows administrator permissions. Saved published server browser routes

can operate with Manager closed; this does not guarantee autonomous local fallback.

Network Drives reminders

Prepare the reviewed Linux SMB gateway and permitted client/hosts first. Import reads

startup definitions without running the script. Install / Repair the protected helper,

Enable management in SYSTEM → Network Drive Routing and inspect Drive Connections.

Add Drive can add only the new connection while management runs; editing an existing

definition requires disabling management. New host authorization requires confirmation.

Settings → This Computer separates refresh/reconnect from route-health monitoring.

Refresh runs immediately. Connect resumes a paused drive; Disconnect pauses it for

the session. Verify drive letter and exact UNC before changing a mapping. Preserve

unrelated mappings. Route switching can interrupt open files even after connectivity

recovers; verify writes in the application using the files.

Diagnose a failure in order

1. Check applied route/profile/endpoint, not only the currently selected editor tab.

2. Extension health → Why this route? → one IPv4/hostname → Check. It reads local

policy without DNS or connection and explains bypass/Ignore, rule and endpoint.

3. Refresh relevant components/VPN/tunnel and inspect last-check age. A listener,

internal destination and website/SMB authorization are separate checks.

4. Notification → Open Log for the exact scoped event. Read stage, destination,

result/exit code. Historical errors are retained; active cards count current issues.

5. Timeout: check network/VPN/endpoint before assuming a bad password. Host-key mismatch:

verify the fingerprint independently. Security block: inspect the exact blocked

connection rather than disabling protection. A zero current-relay count may be idle.

6. Busy fallback ledger: wait briefly and retry; existing connections remain intact.

Browser Disconnect is prioritized; shared cleanup can remain pending acknowledgement.

7. Export Diagnostics if needed, review/redact before sharing and keep secrets/internal

details out of public issues. Never include private keys or vaults in a release.

Update without losing data

Save policy / Save Settings → close dialogs → tray Exit → close extension popups.

Install the approved complete package in its permanent folder. Preserve

%LOCALAPPDATA%\MikeVas_SOCKS5, vault, keys and trusted known_hosts. If an existing

installation asks to create a master password, check its data location before proceeding.

Run Setup again if the executable path or browser registration changed.

When helper code changes, stop active capture/drive management and Install / Repair

the version-matched protected helper with one Windows approval. The main UI stays

unelevated; do not weaken UAC. Reload unpacked extensions in each intended profile.

For native-host startup failure, verify complete files/registration and restart the

affected browser fully after saving work. An installer update is separate from a source

build; public Help/GitHub/store packages require a separate publication step.
