Linux server management

The app has separate This PC and Server sections. No personal server catalogue or credentials are included in source/release packages.

Provisioning and management access

Use an approved Linux host with OpenSSH server/client, systemd, Python 3, NetworkManager and a separately installed SoftEther VPN Client. Administrator review is required for packages, accounts, firewall/SELinux rules and service changes. Components separates This PC checks from read-only Linux Server checks. Remote checks do not install packages or start services. LAN publication additionally needs the configured firewall/SELinux tools; these are not PC prerequisites.

server/bootstrap.py is a first-install administrator helper. It expects the approved SoftEther installation and a controller public key alongside it. It refuses existing accounts/installations; never use it as an upgrade command. mva_server.py implements the restricted JSON control plane, fixed actions and scoped resource ownership. The optional publication/egress scripts and unit examples are site-specific migration tools: review addresses, ports and allowed networks before use. They are not a general unattended installer.

In Connection settings configure host, SSH port, restricted management account, private-key path and trusted known_hosts path. Verify the host fingerprint through a trusted channel. Do not distribute actual keys, credentials, connection.json, profiles.json or diagnostic exports.

VPN and dependent SSH tunnels

Linux Auto Run enables startup when Linux boots; it is independent of Windows startup. Auto Reconnect controls retries on Linux. Overview is informational; use VPN Connections or Server SSH Tunnels for actions. Refresh performs an immediate check; Settings holds independent server status and log intervals.

VPN sessions need a working TAP adapter and address configuration. NetworkManager must use a tun connection in TAP mode, not an Ethernet connection for the SoftEther TAP device. Preserve the management network/default gateway/DNS policy. A session-established result alone does not prove network reachability. Imported profiles and credentials require an approved migration and per-profile connection/IP validation.

Use separate local 110xx and server 120xx SOCKS port ranges. They are distinct from remote SSH ports. A tunnel may reference a server VPN dependency. New SSH listeners are loopback-only. Network publication requires explicit administrator setup and source restrictions; browser clients may then reach the approved server endpoint directly. Local Windows application access can use a secure SSH relay. Linux services continue when the desktop Manager closes. The extension can reuse saved published endpoints offline, and can probe direct endpoint reachability independently; shared Start/Stop still needs management connectivity. Endpoint reachability alone does not prove internal VPN destinations work.

Delete and diagnostics

Select a row, choose Delete and confirm the current connection. This stops an active service and interrupts its users. A VPN with any dependent tunnel cannot be deleted, including a stopped dependent tunnel. Cleanup verifies ownership and removes only the selected managed resources; local backup definitions and original history remain. Partial cleanup retains an incomplete-deletion row for Retry Delete and blocks restart/edit.

The bell distinguishes This PC and Server notifications. Open Log locates the relevant record. App Logs Active Errors / Active Warnings count distinct active issues; All Records retains historical, resolved and unknown records. Server Logs contains server action results; refresh there is independent of local logs. Reading/dismissing notifications does not resolve failures.

Server-first application access and backup

Configure the matching local backup explicitly on the Server SSH Tunnel. Set a local

SoftEther dependency on the local tunnel where needed. Application Routing Connect

prepares the server path through an SSH relay; a published browser SOCKS endpoint is

a different transport. Do not infer pairing from matching names or port numbers.

Only a verified failed primary path may prepare the configured local fallback.

Reviewed Destination Checks can detect an internal VPN/service failure while a

SOCKS listener still answers. Do not invent destination addresses automatically.

Disconnect releases only resources automatically acquired for that consumer and not

shared elsewhere. Linux Auto Run/Auto Reconnect services remain server-owned and do

not stop merely because the desktop UI closes. Deleting or stopping a server resource

is a separate explicit management operation. See procedures.

Tunnels Access

Open the administrator URL while connected to the authorized network or VPN. Sign in using the Tunnels Access password and the current six-digit authenticator code.

Devices & Tokens shows the policy URL and lets administrators create or revoke a token. Copy the URL and token into Automatic → Choose profile → Tunnel server settings in the extension. Save before connecting. The token is shown once.

Use Refresh to update the dashboard without signing out. The dashboard also refreshes every five minutes while your session is valid and displays timestamps in Nicosia time. The first matching routing rule wins. Destinations outside the rules follow the profile default.

Policy download and SOCKS connectivity are checked separately. If the policy loads but a destination fails, check VPN access to its published SOCKS port and the tunnel health.
