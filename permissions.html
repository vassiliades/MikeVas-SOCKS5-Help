Protected background permissions

The main Manager runs as a normal Windows user. A version-matched administrator-owned

helper performs restricted drive host-route, Application Routing and Driver operations.

Install / Repair is available in SYSTEM → Network Drive Routing and Settings → App →

Security. Installation/repair requires one Windows administrator approval. Routine

requests use that installed task without repeatedly elevating the UI.

What is permitted

The executable and task under Program Files are administrator-owned and writable only

by administrators/system. Requests use short-lived tickets and private current-user

pipes with peer-process/executable checks. The allowlist accepts bounded drive-route,

capture and Driver start/stop/restart protocols; it cannot run arbitrary user commands.

Route ownership, allowed host scope, rollback and shared-resource rules remain in force.

No Windows UAC policy is weakened and no unrestricted permanent administrator UI is required.

The task has no login trigger. It is launched on demand. It is not the Linux server,

the SSH supervisor or SoftEther. Driver Active alone does not activate application

interception; drive routing Active verifies owned /32 routes, not SMB authentication.

Updating and repair

1. Save drafts. Stop active Application Routing and disable drive management before

repairing an active helper as requested by the UI.

2. Install the approved complete app update, then Install / Repair the matching helper.

Changed helper code requires a new installation approval; this is expected.

3. Verify permissions/helper state and then re-enable only the required features.

Versions are staged separately and verified before task activation. Failed activation

restores the previous Driver path and retains the previous task target. Updating source

or the ordinary executable alone does not install a protected helper. An incompatible

installed helper reports a repair requirement; do not solve it by disabling security.

SYSTEM → Network Drive Routing and the footer monitor permissions, private helper

communication and owned /32 routes. Checks do not create routes. Standby is normal

with management off. Active requires verified ownership; changed/conflicting routes

are errors. SMB mappings/share access are checked separately in Drive Connections.

Driver and drive routing retain separate activity logs and controls.

Isolated tests validate allowlists, tickets, route ownership/rollback and temporary

Scheduler/pipe exchanges. Elevated installation and reboot acceptance require an

approved real installation; source validation alone does not prove those steps.
