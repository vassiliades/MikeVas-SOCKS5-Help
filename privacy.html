Privacy — MikeVas Manager, server and Tunnels

Updated 10 November 2026. Manager is a local desktop application. Tunnels changes the current browser profile's proxy configuration and may communicate with Connect, Manager or an administrator-configured HTTPS policy server. It is not a full-device VPN or kill switch. SOCKS/SSH operators can observe connection metadata and unencrypted traffic; keep destination HTTPS enabled.

Local state, secrets and policy

The extension stores routing mode, rules, selected/last successful profile, bypass choices, appearance, opaque profile identity and validated policy cache. Each true new browser session starts Direct; the last successful Automatic profile remains saved. With Connect, the one policy device token is protected for the OS user and is not copied into every browser profile. Without Connect, standalone policy URL/token storage is local to that extension profile. Tokens are used only with configured HTTPS services, not as SSH/master passwords. Removing the local token is not server revocation. Revoking a device blocks new downloads, not cached policy or existing SOCKS connections.

Manager master-password vault/SSH credentials and separate private keys stay under local protection. Explicit server management uses authenticated, host-verified SSH to the user-managed Linux server. Saving a server/VPN configuration may send its required credentials to that chosen server. Release archives exclude personal configuration, tokens and keys. Diagnostic exports can contain host/application/path metadata; review them before sharing.

Connect presence and optional diagnostic delivery

The local Connect native channel receives fixed product/browser states, an opaque profile identifier and the version/build identity loaded by the add-on. A connected native channel is not proof of successful authentication, routing or synchronization. Browser/device labels and fixed connection/build summaries can be included in the configured organization server's device view.

Diagnostic delivery is optional and configured in Connect Settings → Tunnels with Send diagnostic metadata to the server and Save diagnostic delivery. It uses the configured HTTPS server and the same protected OS-user device token; it is not an advertising or developer analytics service. Fixed event categories, results, timings, build/state metadata and device/browser labels may be delivered. Passwords, MFA codes, vault field values, workspace contents and page response bodies are excluded from this diagnostic schema. Acknowledged Connect event history is retained for four days; pending events remain until acknowledged, within a bounded 16 MiB journal. Server event history is retained for 90 days. Diagnostic uploads require the optional logs:write device-token scope; an existing policy-only token does not gain that permission automatically. Local histories, pending delivery and server retention are separate. Turning delivery off does not erase already delivered history. Review exported diagnostics before sharing; exports or workspace recovery data may contain information beyond fixed delivery events.

Use Activity and Settings → Tunnels to inspect pending/delivered/rejected counters and delivery errors. Delivered is retained local history, not a lifetime total. Do not post tokens, private hosts, unsanitized exports or personal data in public support issues. Public GitHub Help pages generate normal website requests handled by GitHub; no product credentials are added to Help links.

Actual routing test and rule explanation

Why this route? evaluates a typed destination without making that destination request. Test actual routing is a separate, explicit HTTPS HEAD test. Clicking it requests optional webRequest observation and access to the chosen origin. It sends a cache-busted request without cookies, follows no redirects and reads no response body. The chosen destination sees an ordinary request and its source IP. The browser observes the socket IP. A bounded native DNS query may contact the OS-configured DNS resolver to distinguish destination/proxy addresses. The test URL, response body and socket IP are not added to diagnostic history.

The result is a time-stamped observation for one request. Missing/ambiguous evidence stays Not verified. Chromium cannot distinguish proxy ports sharing one IP. Firefox optional technical/interaction consent governs optional presence reports; declining reports is separate from routing. Store permissions and organizational upload consent are separate controls.

Public Help and control

Public Help uses GitHub Pages and normal website request metadata. It uses no advertising/analytics service or product credentials in Help URLs. Users may disconnect to Direct, remove optional destination permissions, disable diagnostic upload, clear selected local state, stop Connect/Manager or uninstall. Stopping/deleting local software does not erase server/provider copies or cached policy on another device. For support use the publisher contact channel; never publish secrets or unsanitized logs.
